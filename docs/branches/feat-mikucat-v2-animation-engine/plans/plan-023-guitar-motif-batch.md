# Plan 023: Guitar Motif Batch

- Status: complete
- Summary: [Summary 023](../summaries/summary-023-guitar-motif-batch.md)
- Branch: `feat/mikucat-v2-animation-engine`
- Parent: [Plan 021](plan-021-mikucat-v2-animation-engine.md)

## Goal

在已冻结的 Motif 数据契约上，一次性制作六个职责明确的四拍动作，分别补齐 `AUTONOMOUS`、
`ENGAGED` 和 `GROOVE` 的首批动作语汇。六个动作先各自完成数据与自动化验收，再统一进入开发菜单，
由用户在同一轮 Windows dev 中逐项观察；本计划不把它们接入生产规划器。

## Scope

- `AUTONOMOUS`：`tuning-listen`、`lazy-arpeggio`；
- `ENGAGED`：`single-pick-ack`、`two-note-answer`；
- `GROOVE`：`syncopated-chord-walk`、`call-response-sway`；
- 每个动作独占一个源码文件和一个同名数据测试，携带 ID、显示名、所属 Profile、四拍拨弦谱与
  `head / body / leftEar / rightEar / frettingHand` 五条局部轨道；
- 三组并行开发时只创建各自动作和测试，不修改公共类型、注册表、播放器、菜单或文档；
- 六个动作独立通过后，由主线一次性更新注册表、兼容门面和开发菜单，并做播放器回归；
- Windows 端只在整批集成完成后增量同步一次，由用户统一验收六个动作。

不在本计划中：

- 不修改状态机、输入密度归约、cue 协议或状态总线；
- 不实现 Profile 自动选择、概率、冷却、合法前后继或生产随机投放；
- 不修改 A/A′、Cadence、现有两个 `DRIVE` Motif 或其已验收曲线；
- 不在首次批量验收前制作 `A → Motif → A` 上下文衔接；六个新动作只循环自身；
- 不修改模型资源、Live2D 参数清单、特效机或仓库外配置。

## Acceptance

- 六个动作均可通过开发菜单单独选择，切换在下一乐句边界生效，`OFF` 仍能恢复正常模板；
- 每个动作恰好四拍，局部关键帧严格递增并到达小节边界，没有未声明的长空白或第二个 ticker；
- `tuning-listen` 能读作“拨弦—倾听—微调再拨—放松”，倾听段接近静止但不是全身冻结；
- `lazy-arpeggio` 只使用轻拨，身体完成一条慢弧线，按弦手保持同一和弦；
- `single-pick-ack` 只有一个清楚的小回应，其余拍继续低强度演奏；
- `two-note-answer` 在同一琴位完成两次按下—松开，第二音略强，随后作一次头耳确认，但没有
  DRIVE 式重扫；
- `syncopated-chord-walk` 的反拍和三次和弦位置可辨识，身体只稳定换重心；
- `call-response-sway` 的左右问答可辨识但不构成机械镜像；
- 新动作保持开发态隔离，生产规划器输出、现有两个 DRIVE 动作与 A/A′/Cadence 行为不变；
- 完整自动化、TypeScript、定向 ESLint 和差异检查通过，Windows 镜像与 WSL 对应文件一致。

## Risks / Dependencies

- 自动化只能验证节拍、幅度关系和边界，动作观感仍必须由 Windows dev 实机决定；
- 六个动作首次同时出现时，个别动作可能需要多轮视觉微调；本批次先保留原始候选，首轮验收后再
  逐个调整，避免同时改变多个变量；
- 三组并行代码共享同一工作树，但文件所有权互斥；若任一组修改注册表或菜单，会造成冲突并破坏
  批量集成边界；
- 新动作全部采用隔离循环，尚不能证明未来 `A → Motif → A` 衔接自然；衔接属于动作资产通过后的
  下一阶段；
- Profile 字段在本计划中只是规划资格与菜单分组元数据，不得被播放器解释为即时状态输入。

## Verification

三组均先以目标动作模块不存在完成 Red，再分别实现两个动作并通过各自数据测试。主线注册测试随后
先因 `GUITAR_MOTIF_CATALOG` 尚未导出按预期失败；集成后固定八个动作的 Profile 顺序，并确认六个
新动作的开发预览均为单一 Motif 循环。播放器回归逐个启动六个候选、跨越完整四拍边界并检查七个
输出姿态保持有限值。最终 22 个 utils 测试文件全部通过，TypeScript、定向 ESLint 和
`git diff --check` 通过。21 个批次相关文件已增量同步到 Windows 镜像并逐项比对一致。

首次 Windows 批量观察确认六个动作均流畅、循环稳定，但动作辨识度未通过：它们共享四拍载体、
相近的平滑头身弧线和同一吉他本体轨迹，局部耳朵/按弦差异不足以形成可辨识剪影，连续观看时近似
同一个动作。后续停止批量统一调参，改为逐个建立视觉锚点。首个重做对象为
`call-response-sway`：四拍分别落成左侧两次、右侧两次轻量点头，拨弦改为无 `double / accent` 的
`down → up → down → up`，身体只做次级换重心，幅度明确低于 `immersed-double-nod`。新行为测试先
以旧问答弧线和拨弦谱按预期失败，改写后动作、注册表和播放器三项定向回归、TypeScript、定向
ESLint 与差异检查通过。首次单项观察发现第四次点头回收与下一轮左侧准备之间存在纵向反转，视觉上
形成一次头部弹跳；原有回归只检查有限值，未覆盖循环轨迹。新增跨边界连续恢复测试并先确认旧曲线
失败，随后把第四拍末端、循环边界和下一轮起拍改为同一条持续抬升且向左移动的曲线，不以相同端点
制造停顿。三项定向回归、TypeScript、定向 ESLint 与差异检查再次通过；Windows dev 复验确认循环
弹跳消失，`call-response-sway` 动作资产通过并冻结。

第二项逐动作重做选择 `syncopated-chord-walk`。旧动作虽在数据上经过三个和弦位置，但拨弦手没有
空拍，按弦手、身体、头和双耳又同时画连续平滑弧线，实际只能读成普通摆动。新版把按弦手设为主角：
第一拍在和弦一执行 `down → up`，两个半拍 `rest` 分别承载向和弦二、三的换位，和弦二单次下拨，
和弦三执行 `double`，最后半拍 `settle` 单向拾音返回。三个和弦都采用“落下—保持”的重复姿态，
身体延迟承接左—中—右重心，头部只沿琴颈轻微跟随。动作数据测试和播放器循环测试均先以旧实现
按预期失败；改写后确认两个空拍、三个离散停靠点、无 accent、较小头部范围，以及身体跨循环边界
不反向。三项定向回归、TypeScript、定向 ESLint 与差异检查通过，等待 Windows dev 单项验收。
为增加演奏细节，最初在第二、第三和弦间加入单次低头；首轮幅度不可辨识，提高到 `-0.46` 后又被
观察为一次点头。该局部关键帧现已删除，改为横跨整段和弦行进的慢弧线：从第一和弦开始连续下降，
第二和弦进入低位，第三和弦期间持续查看琴颈，再在第三和弦后半逐步抬起。测试固定下降与回收均
单调、低位至少持续 `0.14` 归一化时长，并限制相邻关键帧的最大纵向速度，等待 Windows dev 复验
是否读作持续确认位置而非点头。随后根据可见性反馈把慢弧线最低位从 `-0.44` 加深到 `-0.62`，
保持原有时长并重分配回收关键帧；最大归一化纵向速度仍不超过 `2.11`。Windows dev 复验确认动作
可读且自然，`syncopated-chord-walk` 通过并冻结。

第三项逐动作重做选择 `two-note-answer`。旧版虽然声明两个特色音，实际仍含四次 `pick`、沿琴颈
小幅换位和左右身体转移，视觉上与刚冻结的和弦行进过于相似。新版改为同一按弦位置的两次纵向
“按下—松开”：第一音较轻，第二音更重，四拍中只保留两次真实 `pick`，两音结束后头部和双耳
统一抬起作确认，其余时间由 `rest / settle` 保持生命感。数据测试先以旧实现按预期失败，改写后
固定同一横向位置、两组按压保持、第二次更深、第二音后才抬头，以及循环边界持续回落而不反弹。
动作、注册表和播放器三项定向回归、TypeScript、定向 ESLint 与差异检查通过，等待 Windows dev
单项验收。Windows dev 随后确认新版语义可辨识且循环自然，`two-note-answer` 通过并冻结。

第四项逐动作重做选择 `tuning-listen`。旧版虽具备两次轻拨、倾听和按弦微调数据，但头身仍共享
相近的平滑弧线，单耳和手部变化不足以形成独立剪影。新版把第一次轻拨缩短，延长中间静音窗口；
身体退居近静止背景，头部持续靠向琴颈，一侧耳朵显著抬起，按弦手沿 `-40°` 修正轴完成“保持—
松开—微调—重新按住”，第二次轻拨只负责确认。动作测试先以旧实现按预期失败；实现后数据测试和
播放器运行时测试通过，后者固定头部幅度明显大于身体、单耳主导和微调映射后仍可见。等待 Windows
dev 单项视觉验收。实机随后确认动作可辨识且自然，`tuning-listen` 通过并冻结。

最后一项动作优化选择 `lazy-arpeggio`。旧版虽然声明四次轻拨，但连续 clip、左右平滑摆动和头耳
曲线让它仍像普通四拍循环。新版把每次轻拨拆成半拍 `pick` 与半拍 `rest`，形成四个可分辨音符；
身体只向同一侧完成一次慢速下沉—回收，头部在中段持续低头看弦，按弦手保持同一横向琴位、仅做
轻微压力变化，双耳退居次级余动。数据测试先以旧实现按预期失败；实现后固定四组 `pick / rest`、
身体单一转折点、持续低头而非点头、和弦位置不变及边界回归。播放器测试跳过初始抓弦，只检查稳定
演奏窗口，确认映射后的按弦手没有换位；两项定向测试通过，等待 Windows dev 单项验收。该动作
通过后本计划不再优化 `single-pick-ack`，而是记录最终保留清单并把连贯性验证交回 Plan 021。

Windows dev 随后确认 `lazy-arpeggio` 的四次分离轻拨、持续低头和单侧慢弧线均达到预期。最终冻结
目录共八项：`tuning-listen / lazy-arpeggio / sustain-sway / two-note-answer /
syncopated-chord-walk / call-response-sway / immersed-double-nod / fretboard-slide-accent`。
`single-pick-ack` 不再出现在冻结目录和开发菜单，但其源码、测试和孤立 console 预览保留。Plan 023
至此完成；任何后续边界调整只能在 Plan 021 连贯性阶段处理，不得回头扩充或随机化动作池。
