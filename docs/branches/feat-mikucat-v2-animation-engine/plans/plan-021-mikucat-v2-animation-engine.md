- Status: complete
- Summary: [Summary 021](../summaries/summary-021-mikucat-v2-animation-engine.md)

## Goal

把 MikuCat V2 的独立头、身体、双耳、双手和吉他通道整理为受单一动画机管理的运行能力，并在
保留现有吉他播放器连续性与自主乐句的基础上，升级为有重心、拨弦、反向惯性、强弱和停顿层次的
多通道动画。动画机在同一时间轴上分别承载 `AUTONOMOUS / ENGAGED / GROOVE / DRIVE` 四种演奏
Profile，先逐项验收动作，再实现平滑衔接。动画机同时提供可供状态机分支消费的稳定端口，但不在
本计划内实现角色状态归约、键盘语义或模型外特效。

## Scope

- 保护专有 V2 源素材，只把规范化后的最小运行资源和许可证放入 Tauri 模型目录；
- 固定 V2 通道参数、范围、能力清单和参数所有权/释放语义；
- 把现有四通道吉他播放器迁移为单 ticker、多通道、可测试的乐句动画机；
- 为拨弦手、吉他反向运动、身体重心、头部点拍和双耳反馈编排协调曲线；
- 为已与头部网格解耦的鬓发、刘海、马尾和发带增加统一次级运动，不把头发关键帧复制进各乐句；
- 保留片段连续性、句边界调度、可注入随机源、鼠标交还和模型切换清理；
- 增加最小 durable 动画消费者端口，在安全边界应用最新 `profile / activity / releasing`；瞬时 cue
  由并行特效机和未来 integration plan 处理，不进入第一版吉他规划器；
- 增加仅开发态的 Profile 强制入口，使四种演奏动作可以在状态机合并前分别验收；
- 完成定向自动化检查并由用户在 Windows dev 中做视觉验收。

不在本计划中：

- 不实现 `WAITING > WORKING > RELAXED`、多 Session、接管开关或键盘输入密度归约；
- 不在 Plan 021 重构音符/粒子/贴图/光晕特效机；该职责由并行的 Plan 022 独立实施；
- 不修改 Rust ambient runtime、Codex/Claude hook、named pipe 或仓库外配置；
- 不在首轮设计完整的 `ANGRY` / `RELAXED` 动画，不新增声音或生产依赖；
- 不替用户运行 Windows dev、生成安装包或写入 Git。

## Acceptance

- `mikucat-lived2d-v2/` 中的 `.cmo3` 等设计源不进入 Git 或安装包；内置运行资源引用闭合并随附
  专有许可证，四个表情的中文名称、顺序和稳定身份不回归；
- MikuCat V2 以明确能力清单启用多通道动画，其他内置模型和自定义模型完全沿用原行为；
- 动画机对头、身体、双耳、双手和吉他参数的输出都限制在模型范围内，同一帧没有第二个旁路写入者；
- 退出吉他、切换模型和卸载后外部覆盖被真正释放，physics、鼠标和手动 Expression 能恢复，不出现
  参数黏住、跳零或晚到帧回写；
- 在固定时钟和随机源下，片段交接的位置和速度连续，帧率变化不会明显改变播放速度，不会创建
  重复 ticker；
- 连续 30 秒无键盘输入时，`AUTONOMOUS` 演奏仍有乐句变化且不凝固；动作同时具有停稳/轻缓、
  常奏和短促重音，不是机械重复或全程摇摆；
- `ENGAGED / GROOVE / DRIVE` 可以在开发态被分别强制运行并呈现可辨识但仍属于同一角色的动作
  层次；强制 Profile 不创建第二个 ticker，也不复制状态机的输入计时；
- 拨弦手、吉他惯性、身体重心、头部点拍和耳朵反馈在同一时间轴上协调，重音不打断当前姿态，
  视觉上没有明显相位脱节；
- 吉他态头部运动会带动鬓发、刘海、马尾和发带产生可见但从属的延迟回弹，左右组件不刚性同步；
  不同帧率下结果接近，退出后九个头发覆盖全部释放；
- durable intent 在安全边界采用最新值，不因同模式重复快照重启动画；`releasing` 后只播放一次
  SoftCadence 并平滑进入保持 A；第一版吉他规划器不消费瞬时 cue；
- 动画机不读取具体键值、不维护输入密度/deadline、不创建音符或其他模型外视觉节点；
- Windows dev 中主猫、拖动、缩放、镜像、点击、托盘、输入统计和手动模型切换没有可见回归。

## Risks / Dependencies

- `.cmo3` 的时间戳比当前运行导出更新约 6 分钟；若包含未导出修改，所有参数审计仍只代表旧 moc，
  必须先由用户确认或重新导出；
- v2.1 默认态耳朵 physics 通过 `Param6 / Param7` 增加头部跟随，而动画机仍控制独立的
  `Param16 / Param19`；参数职责不重叠，但叠加后的视觉幅度仍需实机确认；
- `easy-live2d` 的参数覆盖位于 physics 之后且会持续保存；若包装层不能表达释放，退出行为会长期
  压制物理，这是任务 3 的硬前置条件；
- 后续 Editor 导出仍可能重新带回非规范化的表情路径/Name；进入运行资源前必须继续经过引用闭合与
  稳定身份测试，不能整目录覆盖；
- 动画分支与状态机分支都可能改动 `live2d.ts`、主窗口和输入接线。最终合并应重接双方稳定接口，
  不能以整文件覆盖解决冲突；
- 参数范围正确不代表视觉编排自然。自动化测试只能保护所有权、时序和边界，动作观感仍依赖用户
  在 Windows dev 中分轮验收；
- 分离验收如果误做成四套播放器，后续平滑衔接会退化为高风险重写；从第一个 Profile 起必须复用
  同一轨道与时间轴，模式变化只能更新意图；
- Windows dev 和构建始终由用户执行。本分支使用 `D:\VibeTool\BongoCat-animation` 验收镜像；其中
  `node_modules` 与 `target` 是指向 `D:\VibeTool\BongoCat` 对应缓存的目录联接，两个副本不得并发
  编译或运行 dev。Windows RedirectionGuard 要求这些联接由管理员 PowerShell 创建；pnpm 11 还需
  在该临时验收会话关闭 `verify-deps-before-run`，否则会拒绝管理项目根目录外的依赖目录。本计划
  只准备和同步文件。
